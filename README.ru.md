# tg-git-notifications-bot

Self-hosted Telegram-бот, который не даёт пропустить код-ревью в **GitLab** и **GitHub**.
Пишет, когда **ход за тобой**, — и никому не приходится пинговать тебя руками.

- 🔔 Тебя назначили ревьюером
- 🔁 Автор запушил коммиты после твоего ревью · ↩️ ответили на твой комментарий · ✔️ твой тред резолвнули или переоткрыли
- 💬 Новые комментарии в MR, где ты ревьюер или автор · 📣 упоминания
- ✅ Апрувы, 🔄 запросы изменений, ⚠️ конфликты, 🎉 влит / закрыт — по твоим MR
- ⏳ Твой MR ждёт ревью больше суток → одна кнопка оставляет в нём вежливое напоминание
- ⏰ MR ждёт *твоего* ревью 2+ дня → напоминание раз в день, если утренняя сводка выключена (замолкает через 30 дней)
- 🔑 Токен перестал работать → бот один раз скажет об этом, а не замолчит
- Ответить, резолвнуть, заапрувить и отложить можно **прямо из Telegram**
- `/inbox` — только MR, где ход за тобой; `/mr` — все
- Тихие часы и выходные: события копятся и приходят утром одним дайджестом
- Ежедневная сводка в выбранное время (можно выключить) и вечерняя по желанию — что ещё ждёт твоего ответа
- По умолчанию тихо для ботов (renovate, dependabot…) и черновиков на твоём ревью; `/mute` глушит проект целиком
- Многопользовательский: один деплой на всю команду, каждый подключает свой токен
- Один контейнер, SQLite, без публичного адреса (long polling). Интерфейс на русском и английском.

## Быстрый старт

1. Создай бота у [@BotFather](https://t.me/BotFather) и скопируй токен.
2. Запусти где угодно, где есть Docker:

   ```bash
   docker run -d --name git-notify --restart unless-stopped \
     -e TELEGRAM_TOKEN=123456:ABC... \
     -v git-notify-data:/data \
     ghcr.io/isaevdimka/tg-git-notifications-bot:latest
   ```

   или `cp .env.example .env`, впиши `TELEGRAM_TOKEN`, `docker compose up -d`.
3. Напиши боту `/start`. **Первый, кто это сделает, становится админом**; остальных админ пускает
   кнопкой (или впиши их ID в `ALLOWED_USERS`).
4. Выбери GitLab.com / Свой GitLab / GitHub и пришли токен:
   - GitLab: персональный токен со scope **`api`** (с `read_api` будут только уведомления)
   - GitHub: **classic**-токен со scope **`repo`** (упоминания идут через notifications API, fine-grained
     токены туда не пускают)

   Бот сразу удаляет сообщение с токеном и хранит токен зашифрованным.

> Держи `/data` на томе. При старте контейнер отдаёт `/data` своему непривилегированному пользователю (uid 10001) и
> сбрасывает root, поэтому тома Fly, Railway и Render (они принадлежат root) и обычные папки работают без chown.

### Через Makefile (из клона репозитория)

```bash
git clone https://github.com/IsaevDimka/tg-git-notifications-bot && cd tg-git-notifications-bot
cp .env.example .env      # впиши TELEGRAM_TOKEN
make up                   # запустить (make logs · make down · make restart)
make update               # подтянуть свежий образ и перезапустить
make backup               # bot.db + secret.key → ./backups (можно на работающем боте)
```

`make help` покажет все команды, включая `make test` / `make run` для разработки.

## Настройки

| Переменная | По умолчанию | Что это |
|---|---|---|
| `TELEGRAM_TOKEN` | — (обязательно) | Токен твоего бота от @BotFather |
| `DATA_DIR` | `/data` | Где лежат `bot.db` и `secret.key` |
| `ALLOWED_USERS` | пусто | Telegram ID через запятую, которых пускать без одобрения |
| `POLL_INTERVAL` | `180` | Интервал проверки по умолчанию, секунды |
| `MIN_POLL_INTERVAL` | `60` | Минимум, который можно выбрать в `/settings` |
| `URGENT_LABELS` | `blocker,hotfix` | MR с этими метками приходят даже в тихие часы |
| `LOG_LEVEL` | `INFO` | Уровень логов |

Бэкапь `DATA_DIR` целиком (это делает `make backup`): без `secret.key` сохранённые токены не расшифровать.

## Команды

| Команда | Что делает |
|---|---|
| `/start` | Подключить аккаунт GitLab или GitHub |
| `/inbox` | MR, где ход за тобой, и сколько в них непрочитанного |
| `/mr` | Всё, что ты ревьюишь, и все твои MR |
| `/my` | Только твои MR |
| `/watch <ссылка>` | Следить за чужим MR: апрувы, влит, закрыт |
| `/mute` | Заглушить шумный проект (список кнопками или `/mute group/project`) |
| `/lang` | Сменить язык (RU / EN) |
| `/status` | Работает ли бот: последний опрос, ошибки, остаток лимита API |
| `/test` | Образцы всех типов уведомлений |
| `/invite` | Одноразовая ссылка для коллеги (без одобрения админа); пинги ему будут приходить в Telegram |
| `/accounts` | Подключённые аккаунты, их статус, отключение |
| `/settings` | Типы уведомлений, ежедневная сводка и её время, интервал, тихие часы, язык, таймзона |
| `/help` | Список команд |

## Как бот решает, чей ход

- **Ты ревьюер:** ход твой, пока ты не прокомментировал или не заапрувил; после твоего комментария — ход автора;
  автор ответил в твоём треде — снова твой; черновики ничьи.
- **Ты автор:** ход твой при конфликте, при незакрытом треде, где последним писал ревьюер, и когда все нужные
  апрувы собраны (пора мёржить); иначе ход ревьюеров.

## Шаблоны деплоя

В репозитории есть `fly.toml`, `render.yaml` и `railway.json`. Каждому нужен `TELEGRAM_TOKEN` и постоянный
диск, смонтированный в `/data`.

```bash
set -a; source .env; set +a; uv run python -m app
```
